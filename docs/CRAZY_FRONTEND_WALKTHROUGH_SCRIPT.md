## 🔬 Deep-Dive Judge Defense & Technical Q&A

### Q1: "Why use Z3 SMT solving instead of a Python script with if-else conditions?"
> **Answer:**  
> *"If-else scripts suffer from combinatorial explosion. In real-world payroll, salary payments can arrive across multiple tranches, split across different dates, with TDS deductions, PF contributions, reimbursements, and banking holidays.*  
> *Z3 translates this into First-Order Logic constraints over linear integer arithmetic ($\mathbb{Z}$). It doesn't just check equality; it systematically explores the entire hypothesis space ($H_{split}$, $H_{delay}$, $H_{gross}$) in milliseconds. If any valid combination of parameters satisfies the banking inflows, Z3 produces a SAT witness, enforcing mathematical restraint and preventing false allegations. If no combination satisfies the constraints, it mathematically proves UNSAT with an unsat core identifying the exact monetary residual $\Delta$."*

---

### Q2: "Why do you emphasize integer paise arithmetic ($1\text{ INR} = 100\text{ paise}$)?"
> **Answer:**  
> *"IEEE 754 64-bit floating point arithmetic introduces binary representation errors — for example, `0.1 + 0.2 = 0.30000000000000004`. In financial and forensic theorem proving, floating-point rounding creates spurious unsat results or false positives.*  
> *By scaling all monetary amounts to integer paise ($₹95,000.00 = 9,500,000\text{ paise}$), all Z3 arithmetic runs over exact integers ($\text{IntSort}$), guaranteeing 100% mathematical precision with zero rounding artifacts."*

---

### Q3: "What standards does your cryptographic audit trail follow?"
> **Answer:**  
> *"We adhere strictly to **ISO/IEC 27037** (Guidelines for identification, collection, acquisition, and preservation of digital evidence).*  
> *Every log record contains: timestamp, event type, operator identity, target document SHA-256 hash, and the `previous_event_hash`. Any retroactive tampering with a single review log invalidates the subsequent cryptographic hash chain, providing verifiable tamper-evidence."*

---

### Q4: "What is your classification vocabulary?"
> **Answer:**  
> *"Our engine uses strictly calibrated, objective forensic terminology:  
> 1. **Observation** — An operational discrepancy that is mathematically explained by valid hypotheses (SAT).  
> 2. **Inconsistency** — A numerical or textual conflict between cross-evidence documents without structural file tampering.  
> 3. **Potential Manipulation** — Structural, pixel, or typographical anomalies flagged at the file level.  
> 4. **Reviewer-Confirmed** — An inconsistency formally validated and signed off by an authorized forensic auditor."*
